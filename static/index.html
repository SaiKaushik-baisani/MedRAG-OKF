How MedRAG_OKF works

        
My novelty is not RAG. It is making the RAG pipeline trust-aware.

A. Hybrid retrieval + re-ranking. Keyword (BM25 with clinical synonym expansion) and semantic search are fused with Reciprocal Rank Fusion, then re-ranked so the strongest evidence reaches the generator first.

          
B. Evidence verification. Every sentence of the generated answer is checked against the retrieved passages (key terms and any numbers must appear in a passage). Unsupported statements are removed; if too many fail, the system refuses to answer.

          
C. Explainable output. Each answer carries clickable citations, the source document and section, the passage text, scores and a per-stage pipeline trace.

          
D. Query clarification. Vague questions such as "pain" trigger focused follow-up questions before any retrieval happens.

          
E. Safety / triage layer. Pre-defined high-risk patterns (chest pain, stroke signs, breathing difficulty, self-harm, overdose...) short-circuit to emergency guidance. Dosing and diagnosis requests get a caution banner.

          
G. Open Knowledge Format (OKF). The knowledge base is an OKF bundle: one markdown concept per file with YAML frontmatter (type, tags, sources, generated, verified, status, stale_after) and ordinary links between concepts. Those trust fields travel with every cited passage, so each answer shows whether its sources are human-verified, still draft, or past their review date, and the link graph suggests related concepts.

          
F. Evidence score. A 0-1 confidence that the knowledge base really covers the question. Below the threshold the bot says it has insufficient evidence instead of guessing.
